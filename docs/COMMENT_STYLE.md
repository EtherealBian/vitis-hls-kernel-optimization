# 中文注释与源码规范

## 适用范围

本规范用于参赛原创或实际修改的 RTL、HLS C/C++、Python、XDC 和构建脚本。
AMD/Xilinx 等第三方原始文件保留上游版权和注释，不统一改写，也不标记为原创。

## 文件头

手写源码文件头应包含文件名、功能摘要和作者 Ethereal。算法文件还应说明输入/
输出数据格式、控制参数、帧长或位宽约束。项目不使用带姓名的方括号批注前缀。

## 内联注释

- 说明“为什么这样实现”、接口契约、状态转换、边界条件和资源/精度权衡。
- RTL 注释应覆盖时钟/复位、组合与时序边界、握手、背压、CDC 和位宽转换。
- HLS 注释应覆盖顶层接口、DATAFLOW/PIPELINE、循环次数、定点量化和资源映射。
- Python 注释应覆盖硬件寄存器含义、DMA 缓冲区所有权、异常清理和单位。
- 避免逐字复述语句、无上下文的“修复”“新增”、表情符号式批注和失效说明。

## 编码与换行

所有文本源码统一使用 UTF-8（无 BOM）与 LF 换行。`.editorconfig`、
`.gitattributes` 和提交前检查共同约束格式；二进制 bitstream 不参与文本转换。

## 自动生成 RTL

Vitis HLS 和 Vivado 生成的 RTL、IP 缓存、DCP、运行目录不纳入仓库，也不逐文件
补注释。公开的是生成它们的 HLS/RTL 源码、Block Design、约束和构建说明。
