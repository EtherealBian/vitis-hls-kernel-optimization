# 第三问：Cholesky 分解原代码功能与优化说明

## 1. 项目任务与测试对象

第三问实现的是面向 FPGA 高层次综合（HLS）的 **Cholesky 分解**。本目录中的测试配置针对：

- 矩阵规模：`3 × 3`
- 数据类型：复数定点数 `hls::x_complex<ap_fixed<16, 1, AP_RND_CONV>>`
- 输出形式：上三角矩阵（`MATRIX_LOWER_TRIANGULAR = 0`）
- HLS 目标时钟周期：`7.70 ns`

主要分析文件如下：

- `baselines/solver/cholesky.hpp`：优化前实现；
- `solver/L1/include/hw/cholesky.hpp`：优化后实现；
- `docs/CHOLESKY.md`：整理后的优化原理与实验记录；
- `solver/L1/tests/cholesky/complex_fixed_arch0/reports/csynth.xml`：最终 C 综合结果；
- `solver/L1/tests/cholesky/complex_fixed_arch0/reports/csim.log`：C 仿真结果；
- `solver/L1/tests/cholesky/complex_fixed_arch0/reports/cosim.rpt`：RTL 协同仿真结果。

## 2. 原代码实现了什么功能

### 2.1 Cholesky 分解的数学目标

对于 Hermitian（共轭对称）正定矩阵 `A`，Cholesky 分解将其写成：

```text
A = L · Lᴴ
```

其中 `L` 为下三角矩阵，`Lᴴ` 表示 `L` 的共轭转置。如果要求输出上三角矩阵，则可等价地输出 `U = Lᴴ`，满足：

```text
A = Uᴴ · U
```

本题配置选择输出上三角矩阵，但代码内部仍按照逐行构造下三角因子的方式计算，最后通过共轭和转置关系写出上三角结果。

### 2.2 顶层数据流

顶层 `cholesky()` 接口使用 HLS Stream 接收和输出数据，其工作流程为：

1. 从输入流依次读取 `3 × 3` 个复数元素，保存到局部矩阵 `A`；
2. 调用 `choleskyTop()` 完成矩阵分解；
3. 将结果矩阵逐元素写入输出流；
4. 返回状态码，用于表示输入矩阵是否满足分解条件。

### 2.3 原始 `choleskyAlt` 架构的计算流程

当前复数定点类型默认使用 `ARCH = 1`，对应 `choleskyAlt` 架构。原代码按行依次计算矩阵，外层第 `i` 行必须等前面的行完成后才能开始，因为当前行会使用已经求出的历史结果。

对于第 `i` 行、第 `j` 个非对角元素（`j < i`），执行：

```text
L(i,j) = [A(i,j) - Σ L(i,k)·conj(L(j,k))] / L(j,j)
                     k=0...j-1
```

代码没有在每次使用时重新做除法，而是将对角元素的倒数保存在 `diag_internal[j]` 中，随后使用乘法：

```text
L(i,j) = product_sum × diag_internal[j]
```

在一行的全部非对角元素计算完成后，累加其模平方：

```text
square_sum = Σ |L(i,j)|²
```

再计算当前对角元素：

```text
L(i,i) = sqrt(A(i,i) - square_sum)
```

同时计算并保存后续行需要的对角元素倒数：

```text
diag_internal[i] = 1 / sqrt(A(i,i) - square_sum)
```

对于复数输入，乘积中使用共轭运算；理论上正定 Hermitian 矩阵的对角计算结果应为非负实数。`cholesky_sqrt_op` 会检查负值，并通过返回码报告无法进行正常 Cholesky 分解的情况。

### 2.4 原代码的数据存储方式

原始 `choleskyAlt` 使用一维压缩数组：

```cpp
L_internal[(N * N - N) / 2]
```

它只保存下三角中的非对角元素，从而节约存储资源；另用 `diag_internal[N]` 保存对角元素的倒数。该方案资源利用较紧凑，但同一个数组端口需要服务多个循环迭代，限制了并行读写能力。

### 2.5 原代码的主要性能瓶颈

原实现功能完整，但硬件执行时间较长，主要原因包括：

1. **非对角元素串行计算**：`j` 循环逐项计算一行中的各个元素；
2. **内积串行累加**：每个元素对应的 `k` 循环逐项完成乘加；
3. **压缩数组端口受限**：多个并行运算无法同时读取所需的历史元素；
4. **倒数平方根代价高**：定点版本先调用通用平方根，再执行 `1 / sqrt(x)`，形成较长的平方根和除法路径；
5. **循环控制开销明显**：对于固定的 `3 × 3` 小矩阵，串行循环的控制开销占比较高。

需要注意的是，Cholesky 分解的行与行之间存在真实的数据依赖，因此不能简单地把外层 `i` 循环完全展开。可重点优化的是每一行内部彼此可并行的计算。

## 3. 我做了怎样的优化

### 3.1 将内部矩阵改为二维完全分割存储

优化后将压缩的一维数组改成完整二维数组：

```cpp
L_internal[N][N]
```

并对两个维度以及对角倒数数组进行完全分割：

```cpp
#pragma HLS ARRAY_PARTITION variable=L_internal complete dim=1
#pragma HLS ARRAY_PARTITION variable=L_internal complete dim=2
#pragma HLS ARRAY_PARTITION variable=diag_internal complete
```

完全分割后，各元素可以映射为独立寄存器，多个计算单元能在同一周期并行读取不同位置的数据。代价是使用更多寄存器、LUT 和布线资源，但对本题固定的 `3 × 3` 小矩阵而言，这种“以资源换时间”的方式非常有效。

### 3.2 完全展开行内 `j` 循环和内积 `k` 循环

优化后的循环改为固定上界，并配合条件判断与 `UNROLL`：

```cpp
for (int j = 0; j < N; ++j) {
#pragma HLS UNROLL
    if (j < i) {
        // 计算当前行的非对角元素
    }
}
```

内积的 `k` 循环也采用相同方式完全展开。这样，综合器能够为多个复数乘法和加法实例化并行硬件，显著减少原来逐项循环带来的延迟。

外层 `i` 循环仍然顺序执行，因为第 `i` 行依赖前面各行的结果。这保留了算法的正确依赖关系，同时最大化行内并行度。

### 3.3 使用分段部分和并行归约

原代码在计算每个 `L(i,j)` 后，直接向同一个 `square_sum` 连续累加，形成循环携带依赖。优化后增加完全分割的数组：

```cpp
square_partial[N]
```

每个展开的 `j` 分支把自己的模平方写入独立位置，最后再通过展开循环完成归约：

```text
square_sum = square_partial[0] + ... + square_partial[N-1]
```

这样消除了不同 `j` 迭代对同一个累加器的直接竞争，更适合并行硬件结构。

### 3.4 增加流水线与内联控制

优化代码在关键函数及初始化循环中加入了 `PIPELINE II=1`，并对主要计算函数使用 `INLINE off`，使其保留清晰的硬件模块边界。二维数组初始化的列循环被完全展开，行循环进行流水化。

这些指令的作用是减少循环启动和控制开销，并让综合工具尽量实现每周期接受一次新迭代的局部数据通路。不过，整个矩阵分解仍受行间依赖及顶层读写流程限制，所以顶层事务间隔并不等于 1。

### 3.5 用分段初值和牛顿迭代优化定点倒数平方根

原来的定点倒数平方根采用：

```text
sqrt(x) → 类型转换 → 1 / sqrt(x)
```

优化后不再直接使用通用除法器，而是先根据 `x` 所在区间选择一个常数初值，再执行牛顿迭代：

```text
y(n+1) = y(n) × [1.5 - 0.5 × x × y(n)²]
```

代码按 `x < 0.0625`、`x < 0.25`、`x < 1`、`x < 4`、`x < 9`、`x < 16` 等范围选取初值；一般执行 3 次迭代，较大输入执行 6 次迭代，并将关键乘法绑定到 DSP。

实验记录中将它概括为“LUT + Newton”，但从最终代码看，更准确的说法是 **分段常数初值 + Newton-Raphson 迭代**，并没有使用按地址索引的 ROM 查找表。该优化缩短了通用平方根加除法形成的长延迟路径，但属于近似计算，会带来一定数值误差。

### 3.6 补充多种架构入口

优化后的文件还补充了 `choleskyBasic`、`choleskyAlt2` 以及按 `TRAITS::ARCH` 选择实现的分支，便于在低资源、平衡型和高并行架构之间切换。

但本题实际复数定点调用没有把测试文件中定义的自定义 traits 显式传给模板，因而使用库的默认复数定点 traits，即 `ARCH = 1`。所以本次 6.912 ns / 1407 周期结果对应的核心路径仍是经过上述修改的 `choleskyAlt`，新增的其他架构不是本次性能提升的直接来源。

## 4. 优化前后的结构对比

| 对比项 | 原代码 | 优化后代码 |
|---|---|---|
| 内部数据存储 | 一维压缩下三角数组 | 完整二维数组 |
| 存储端口 | 数组端口限制并行访问 | 两维完全分割，可并行访问 |
| 行内 `j` 循环 | 串行 | 完全展开 |
| 内积 `k` 循环 | 串行 | 完全展开 |
| 模平方累加 | 单一累加变量 | `square_partial` 分支计算后归约 |
| 倒数平方根 | 通用 `sqrt` 后再除法 | 分段初值 + 牛顿迭代 |
| 乘法资源映射 | 主要由工具自动决定 | 关键定点乘法显式绑定 DSP |
| 优化策略 | 偏重节省资源 | 针对小矩阵，以资源换低延迟 |

## 5. 优化效果

实验记录给出了两轮主要优化：

| 阶段 | 主要改动 | 总执行周期 | 相对上一阶段下降 |
|---|---|---:|---:|
| 原始实现 | 串行行内计算、通用倒数平方根 | 4919 | — |
| 第一轮 | 数组完全分割，`j/k` 循环展开 | 3191 | 35.1% |
| 第二轮 | 流水化、部分和并行、近似倒数平方根 | 1407 | 55.9% |

从原始的 4919 周期下降到 1407 周期，总体减少：

```text
(4919 - 1407) / 4919 ≈ 71.4%
```

因此，本次优化的核心成果是在保持行间依赖不变的前提下，把行内计算由串行结构改造成高度并行的数据通路，并针对定点倒数平方根这一高延迟运算做了专门近似实现。

## 6. 最终综合与协同仿真结果

### 6.1 时序与延迟

最终 `csynth.xml` 中的顶层综合结果为：

- 目标时钟周期：`7.70 ns`
- 估计时钟周期：`6.912 ns`
- 估计最高频率：约 `144.68 MHz`
- 单次事务综合延迟：`179` 周期
- 顶层事务间隔：`180` 周期

RTL 协同仿真报告为：

- Verilog 协同仿真：`Pass`
- 单次测试延迟：`175` 周期
- 事务间隔：`176` 周期
- 8 组矩阵的总执行时间：`1407` 周期

因此，目录名中的“1407”是整次协同仿真的总执行时间，不是一次 Cholesky 分解的延迟。单次延迟应分别按综合报告的 179 周期或协同仿真的 175 周期表述。

### 6.2 资源占用

最终顶层综合资源如下：

| 资源 | 使用量 | 器件总量 | 利用率 |
|---|---:|---:|---:|
| BRAM_18K | 0 | 280 | 0% |
| DSP | 152 | 220 | 69.09% |
| FF | 14527 | 106400 | 13.65% |
| LUT | 19330 | 53200 | 36.33% |

结果说明优化显著依赖 DSP 并行乘法器：DSP 使用率已接近 70%，换来了明显的延迟下降。BRAM 使用量为 0，是因为小规模、完全分割后的内部数组主要被实现为寄存器和组合逻辑。

## 7. 正确性结果应如何理解

C 仿真日志最终显示 `TB:Pass` 且为 `0 errors`，RTL 协同仿真也显示 `Pass`，说明：

- HLS C 模型满足当前测试程序设定的通过条件；
- 生成的 RTL 与 C 模型在当前测试范围内行为一致。

但日志中只有矩阵类型 1 显示 `L Matching = 1`；矩阵类型 2、3、4、5、6、7、9 均为 `L Matching = 0`。测试仍然通过，是因为测试程序真正用于判定失败的条件是 DUT 残差比值不超过阈值 30，而不是要求每个输出元素与 LAPACK 结果完全一致。

这意味着当前近似倒数平方根方案通过了现有的残差标准，但在多数测试上改变了分解因子的逐元素数值。RTL `Pass` 不能替代对数学精度的进一步验证。如果应用对数值精度要求较高，还应增加：

- 更多随机 Hermitian 正定矩阵；
- 接近奇异或条件数较大的矩阵；
- 更宽输入动态范围；
- `A - UᴴU` 的绝对误差、相对误差和最大元素误差；
- 与 LAPACK 结果的定点容差比较。

## 8. 优化的适用范围与注意事项

1. **当前优化非常适合固定的小矩阵。** 完全分割与完全展开会使资源规模大致随矩阵维度快速增长，矩阵变大后不宜直接照搬。
2. **资源代价较明显。** 152 个 DSP 已占器件的 69.09%，若同一 FPGA 还要部署其他计算模块，需要重新平衡吞吐率与资源。
3. **倒数平方根是近似计算。** 分段初值有限，输入跨越较大动态范围时可能需要更合理的归一化、更多分段或误差受控的查找表。
4. **外层行依赖不能随意展开。** 预先计算所有对角元素或完全展开行循环会破坏 Cholesky 的数据依赖，实验中没有采用这些方案是合理的。
5. **架构配置需要进一步统一。** 当前测试宏中虽然设置了 `SEL_ARCH = 0`，但顶层模板调用未传入自定义 traits，实际走的是默认 `ARCH = 1`。建议后续显式传入 traits，避免配置值与综合实现不一致。

## 9. 总结

原代码完成了复数定点 Hermitian 正定矩阵的 Cholesky 分解，通过逐行计算非对角元素、对角平方根和对角倒数，最终输出上三角分解矩阵。其主要问题是行内循环串行、压缩数组端口受限，以及通用倒数平方根路径延迟较高。

优化后的方案通过二维数组完全分割、两层循环完全展开、部分和并行归约、局部流水化，以及分段初值配合牛顿迭代的定点倒数平方根，将实验记录中的总执行周期由 4919 降至 1407，下降约 71.4%，估计时钟周期达到 6.912 ns。代价是 DSP 和 LUT 占用显著提高，并且近似倒数平方根降低了逐元素数值一致性。因此，这是一种针对 `3 × 3` 小规模矩阵、以硬件资源和部分精度换取低延迟的优化方案。
